## Unreleased

## 0.16.0 – unreleased
- With several heating circuits, the house contains a compact room overview: one accessible and tappable row per circuit with its name, actual and target temperature, plus a colour dot for below, within or above 0.5 K of the target. Circuit status lines now contain only the operating mode; a single circuit keeps the existing large room display (#140).
- The ebusd preset groups mappings by their complete MQTT entity stem and selects one coherent, most-complete daemon instead of mixing fields from multiple legitimate ebusd instances. The diagnostic report lists competing groups, and `prefix` accepts a full stem for explicit selection (#197).
- Luxtronik is marked confirmed on a real water-to-water installation with combined storage and a fresh-water station; air and brine installation reports remain welcome (#75, #208).
- Vaillant/myPyllant is marked confirmed on a real aroTHERM plus installation; installation-specific power-source and external-meter entities remain manual overrides (#211).
- New `narrow_values` option keeps buffer middle/bottom temperatures and configured heating-circuit return labels visible below 500 px while the other responsive collision protection remains active (#212).
- New `buffer_values: equal` mode gives every configured buffer temperature the same visual weight and distributes one, two or three values evenly over the tank; the default top-emphasis layout is unchanged (#213).
- A hot-water tank without `dhw_top` keeps its unmeasured upper zone neutral instead of colouring the whole tank from a cooler middle or bottom sensor; measured lower zones and existing tanks with a top sensor are unchanged (#215).
- New `entities.dhw_loss_sensor` selects the plain temperature sensor used to fit the hot-water standby-loss slope, while all configured real tank sensors continue to detect draw-off and unexplained heating (#216).
- card-mod colour variables survive the initial render and later card rebuilds because the card no longer replaces integration-owned styles in its shadow root (#164).
- Manual and Energy-dashboard PV, battery and grid sources consistently accept W, kW and MW as live power, convert them to watts, and keep Wh, kWh and MWh classified as energy counters (#210).

## 0.15.0 – 2026-10-30
- New card without a detected integration: the card picker no longer falls back to `preset: lambda`. The card starts without a preset and shows a short start hint with a link to the supported integrations instead of "No entities of this preset found" (#142). An explicit preset that finds nothing keeps its hint; a card with any own entity, error entity, badge or quick control draws as before.
- New card with two heat pump integrations for the same unit (myPyllant and ebusd, ViCare and Open3E): the card picker now takes the preset that finds the most live core entities (mode, compressor, power, flow, return, hot water), not the first one in the list; on a tie the list order decides (#143).
- Editor: presets whose integration is installed come first in the preset list, best match first, marked "Detected (N entities)"; the helper of the preset field names further detected presets, for example myPyllant next to ebusd (#145).
- Editor: every entity field says what it expects, in English and German: the unit (°C, l/h or l/min, W or kW, bar, kWh), "on/off" instead of "binary", and for the three flow rates which loop they belong to (heat pump loop with the primary pump, brine or well loop, heating circuit). Reported by Gothmoth88 (#180).
- Editor and diagnostic report check the mapped entities (#192): an entity that does not fit its field (a temperature as the diverter valve, a select as the room temperature, a start counter as the heater), one entity in two fields that measure different things (heat pump flow as buffer top, one flow rate for the heat pump and the source loop), source fields set on an air heat pump, and daily values no day can bring (the total starts as starts today). The findings show above the editor form and at the field, and in a new "Checks" section of the report; the card itself shows nothing. One table of field kinds now drives the checks, the entity pickers and the on/off fields.
- Editor checks and entity pickers accept other spellings of a unit: `ºC` (with the ordinal sign some integrations use), `℃`, `℉` and hours written as `hours` or `hrs` (found in the pre-release review of 0.15.0).
- Editor: the entity pickers of measurement fields offer the entities that fit (temperature fields: °C sensors and thermostats; power, energy, pressure and flow rate fields: their units), found by unit or device class, so sensors of MQTT integrations without a device class are offered too. An entity already mapped stays selectable. The switch "Show all entities in the pickers" lifts the filter; it belongs to the editor and is not saved in the card (#194).
- Editor: each entity group shows its core fields first (heat pump: mode, compressor, power, heat, flow, return, flow rate, outdoor, valve; storage: hot-water top and target; circuits: flow, return, pump, room) and keeps the others in a "More fields" block, which opens as soon as the configuration sets one of them. An air heat pump no longer shows the source flow rate, source outlet and brine pressure fields, unless the configuration sets one (so it can still be cleared). Nothing changes in YAML (#193).
- Editor: entities the preset would use but that are disabled in Home Assistant are named in the hint box, with the field they would fill, for example Luxtronik's "Current power consumption" (#146). The editor reads the entity registry for that (administrators only; other users see no change) and keeps only id, integration, translation key, device and name. Nothing is enabled automatically.
- Diagnostic report (#147): a new "Detection" section says what the detection of the configured preset looked for (integration, translation keys or entity id patterns) and whether it found it, which heat pump integrations this Home Assistant has (platform names and entity counts only) and which presets match, best first. Each mapped entity says where it comes from, `[preset]` or `[own]`, and names the integration of an own entity that is not the preset's (`[own · mypyllant]` next to the ebusd preset). Cleared keys and unmapped keys take one line each, with the note that an empty key is fine when the installation does not have it; keys of circuits beyond `hc_count` are left out.
- The card warns when an older copy of itself took the element names first, as happens with the dashboard resource from before the rename next to the new one: a console warning with both versions and the scripts on the page, and once per browser session a Home Assistant notification that says which resource and folder to delete. The diagnostic report lists every script of the card that the page loaded. From this release on, the card classes carry a version marker (`hfcVersion`) (#171).
- The card picker always shows the card as "Heat Pump Hydraulic Card", with a shorter description that names the main brands (#144).
- Open3E preset: confirmed on a real installation with two heating circuits, so it is no longer marked "untested". Added from the card picker, the card counts the circuits the integration reports; each circuit's emitter is set with `hc_type` to `hc6_type`. Contributed by udochrist (#168).

WPM 3, WPM 3i and the LWZ family still follow the integration source only. The preset notes record what the report answered (heat pump flow sensor, unavailable optional hardware, hot water flag during heating) and what is still open (#154).

## 0.14.0 – 2026-10-29
- Combined (layered) storage (#50): `storage: combined`, also in the editor, draws one tall tank with the hot-water zone on top and the heating zone below instead of a hot-water tank and a buffer. The six storage keys (`dhw_top` to `buffer_bottom`) are heights in the one tank, top to bottom, and the tank colour runs over every sensor at its height. The diverter valve charges the top zone for hot water and the middle for heating, the circuits draw from the heating zone like from a buffer, heater rods and solar thermal sit in their zone. Not together with `series_buffer`; presets never set it. New demo setup "Combined storage".
- Hot-water preparation `dhw_type` (#50, also in the editor): `coil` (default), `fresh_water` and `tank_in_tank`. A fresh-water station is drawn beside the hot-water zone of a combined storage, or, with separate storages and a parallel buffer, instead of the hot-water tank on top of the buffer, without a diverter valve; hot-water operation then heats the buffer. A tank in tank is an inner tank in the hot-water zone of a combined storage. New demo setup "Fresh-water station".
- The `dhw_loss` tile with a combined storage needs the pump of every heating circuit and leaves out every standby window in which one of them runs, because the circuits draw heat from the same tank; with one circuit unmonitored it is not offered. With a fresh-water station on the buffer it is not offered either, as there is no tank.
- New demo setups "Combined storage, tank in tank" and "Combined storage, fresh-water station".
- Without a parallel buffer (direct system or series buffer) the heating circuits and the heat pump are drawn as one water loop (#124). A circuit pump that runs while the heat pump idles now moves the water through the heat pump as well, without heat at the emitter; a primary pump that circulates while the circuit pumps are off moves it through the circuits, whose pumps stand still; while the diverter valve stands on hot water (during a charge, and after it while the valve stays there) it closes the heating side and a running circuit pump moves no water. With a parallel buffer nothing changes.
- Several heating circuits: the first stretch of flow and return that feeds all circuits is drawn as a trunk of its own and flows whenever any circuit runs. Before, it belonged to circuit 1, so with circuit 1 off and another circuit on the flow started at a standing pipe.
- Combined storage: a sensor without a value (unavailable) takes the colour of the nearest sensor instead of drawing a grey band in the tank.
- Documented: cooling runs through the heating zone of a combined storage; a fresh-water station on the buffer leaves solar thermal out; hot-water mode without any hot-water key shows the running heat pump without flowing pipes.
- With several heating circuits, circuit 1 shows its room temperature and target (`room`, `room_target`) in its status line like circuits 2 to 6 (#135); the house keeps showing them.
- The PV, battery and grid dots and the hot-water coil loop their animation without a jump (#135): each dash animation now moves by whole periods of its own dash pattern.
- The heating pressure label starts right of the storage column, so a long text such as "Heizungsdruck 1,8 bar" is no longer covered by the buffer (#129).
- `valve_map` in the visual editor (#126): with a mapped valve, "Advanced" shows "Valve states for hot water" and "Valve states for heating" as comma-separated raw states, with the current state of the valve as help. Only differences from the preset are written back, and a map written in YAML stays as it is unless the fields are changed. The editor warns when a numeric valve sensor has no map, because 1 is then read as hot water. `valve_map` values are accepted in any case and as `heat`, `hot water` or `hot_water`; an invalid value is named in the error.
- The diagnostic report lists the value maps (`valve_map`, `mode_map`, `dhw_mode_map`, `buffer_mode_map`, `hc_mode_map`, `program_map`) with their source, preset or configuration, and names a map placed under `entities` by mistake (#125).
- The diagnostic report names the hydraulic options in one line: storage, hot-water preparation, series buffer (with or without bypass valve) and primary pump.
- The visual editor warns when a value map such as `valve_map` sits under `entities`, where the card ignores it.
- The visual editor no longer writes `series_bypass: true` into every configuration it saves; the option is only kept as `false` next to a series buffer.
- Wolf: the `wolf` preset is confirmed on a real installation (CHA with `wolf_smartset` 0.5.0, card 0.13.1) and no longer marked untested. The `wolflink` branch is built from the entity registry and states of the same installation.
- Internal: the flow logic (operating state, open side of the diverter valve, series-buffer bypass, which pipe, circuit and loop flows) is decided in one place, `_flowModel()`, and the drawing only reads from it. Nothing changes on the card; a new topology test (`test/topology.html`) proves this with a snapshot of the drawing for every demo setup, layout and scenario, and checks about 140 generated storage and circuit combinations for loose pipes, flow into closed pipes, overlapping parts and keyboard access.

## 0.13.1 – 2026-10-27
- Heating circuit 1 is drawn when there is a buffer, even without an entity of the circuit itself (`hc_flow`, `hc_mode`, `hc_pump`), as it was without a buffer. It hangs on the buffer, takes the colour of its pipes from the buffer temperature and runs while the heat pump heats. Before, `hc_count: 1` showed no circuit and no radiators until a circuit entity was mapped, while `hc_count: 2` drew both (#118).
- Vaillant (myPyllant): the preset is found when the entity ids end in a number (`sensor.home_energy_manager_state_2`, as Home Assistant adds it to an id that was already taken). Before, the home was not detected and every entity of the preset showed as "not found". The plain id wins over the numbered one, and the same tolerance applies to all entities of the preset (#120).
- Vaillant (myPyllant): without zone sensors the zone thermostat (`climate.<home>_zone_…`) serves as room temperature and target; zone sensors still win (#120).
- Wolf (`wolf_smartset`): the DHW target comes from the sensor `set_dhw_temperature_adjusted`, the effective target that drops to 10 °C while hot water is off; the number `set_dhw_temperature` is the fallback. Before, the card showed the configured value while hot water was off.
- Wolf (`wolf_smartset`): the heating program chip comes from the mixer circuit demand (`mixer_circuit_demand`): "Automatik aus" shows night, party, holiday and Sparbetrieb (eco) are recognised. Confirmed on the reference installation for "Automatik ein" and "Automatik aus".

## 0.13.0 – 2026-10-27
- New preset `stiebel_isg` for Stiebel Eltron and Tecalor heat pumps with an ISG (WPM 3, WPM 3i, WPMsystem, LWZ) through the [Stiebel Eltron ISG](https://github.com/pail23/stiebel_eltron_isg_component) integration (HACS, `stiebel_eltron_isg`), requested in #69. Entities are found through translation keys, so entity ids and the Home Assistant language do not matter. The mode comes from the compressor, defrost and hot water flags (the integration has no status sensor); flow and return of heat pump 1, flow rate, hot water, buffer, heating circuits 1 to 3, inverter power (WPMsystem), refrigerant circuit, quick controls, the fault flag and heat and electricity counters per use as tiles. Hardware that is not installed reads unavailable in the integration and is left out. Built from the integration source and marked untested; cooling is not shown. See `docs/presets/stiebel-isg.md`.
- New preset `bosch_buderus_heating` for Bosch and Buderus heat pumps in the Home Comfort app (Bosch/Buderus Home Comfort integration, PointT cloud), using stable registry identities for measurements, statistics and details. The default controls are limited to the selected heating and DHW circuit modes and one-time DHW charge; further controls are opt-in. The card and editor share registry loading and check only the integration's registered states during updates. A mapping guide, synthetic regression checks and an upstream manifest. The automatic preset still needs its own installation test.
- Wolf: the `wolf` preset also serves the custom `wolf_smartset` integration (Wolf SmartSet read/write, HACS). Its entities are found through the entity registry by translation key, so entity ids, device names and the Home Assistant language do not matter; it wins when both integrations are installed. Needs `wolf_smartset` 0.3.0 or newer. With `hc_count: 2` the preset no longer repeats circuit 1 as circuit 2. Details in `docs/presets/wolf.md`.
- New option `primary_pump` (also in the editor, default from the preset): draws the heat pump's own primary pump on the flow pipe next to the heat pump block, centred under the flow temperature and over the flow rate. It turns while the flow rate is above 0, else with the heating or hot-water loop. A single direct circuit without a `hc_pump` sensor then shows no pump of its own. The HeishaMon preset turns it on, because the Aquarea primary pump sits in the outdoor unit (monobloc) or the hydro module (split) and also runs for hot water.
- Samsung and Kronoterm: the presets turn on `primary_pump`, so the primary pump of the heat pump (Samsung: the water pump 0x4089, which also runs for hot water; Kronoterm: the main circulation pump, register 2038) is drawn on the flow pipe next to the heat pump block instead of as a pump of the heating circuit. A single direct circuit without a pump signal (Samsung) then has no pump of its own; the Kronoterm loop pumps stay in their circuits. `primary_pump: false` brings the old drawing back.
- New entity key `fan_speed` (rpm or binary): the fan of the unit drawing turns while it is above 0 (or on), and faster at a higher speed. Without it the fan follows the running state as before. The HeishaMon preset maps `fan1_motor_speed`, so the fan also turns while it runs on after the compressor stops. An `unavailable` or `unknown` fan entity counts as missing, so the fan then follows the running state.
- New option `series_buffer` (default `false`, also in the editor): draws a series buffer in the return of the heating circuits with a 3-way bypass valve (A: bypass from the flow, B: circuit return, AB: buffer). Normally the circuit return runs through the buffer. While the new entity `bypass_valve` is on, or without it while the heat pump defrosts, the flow runs straight into the buffer and the circuits stand still, so the heat pump defrosts from the buffer water. The buffer needs no sensors; a parallel buffer with its own sensors (`buffer_top`, `buffer_mode`) wins. New text keys `series_tank` and `bypass`.
- Series buffer without a bypass valve: set `series_bypass: false` (default `true`, in the editor only with `series_buffer`). The card then draws no valve, the circuit return always runs through the buffer and the circuits keep running in defrost. Without this option and without `bypass_valve`, the valve follows the defrost signal and stops the circuits while the heat pump defrosts.
- Flow animation: the dash speed is proportional to the flow rate (1000 l/h = one dash cycle per second), so the water visibly speeds up and slows down with the pump. Before, 600 and 1200 l/h looked almost the same.
- Sniffing: the heat waves above the emitter stop, because the circulating water brings no heat to the circuit (only without a buffer).
- Heating curve shift: new entity keys `hc_curve_offset` (and `hc2_curve_offset` to `hc6_curve_offset`), read only. With a shift, the label above the circuit pump shows the target with its parts, for example "Target 36 °C (curve 34 °C + 2 K shift)": the target already contains the shift, so the curve is target − shift. The label ends at the pump; where it does not fit, the word for the shift and then the brackets are left out. The flow temperature moves below the pump, the flow rate below it. A shift is a difference, so °C shows as K. Without the key the label stays as before. The HeishaMon preset maps `number.<prefix>_main_z1_heat_request_temp` (`z2_` for circuit 2) when the heating mode is "compensation curve"; in direct mode that number is the flow target itself and is left out. New text keys `curve_offset` and `curve_shift`.
- Heating curve shift: the flow temperature under the circuit comes only from the circuit's own flow sensor (`hc_flow`). Without one the heat pump's flow stands only at the VL label and is not shown twice.
- Heating curve shift: with a shift of 0 the label shows only the target ("Target 34 °C"), without "(curve 34 °C + 0 K shift)".
- New entity key `pv_boost` for a PV surplus mode (a binary entity that is on, or a power above 0), requested in #108. The card shows a "PV surplus" chip, the timeline turns the heating periods in which the mode was active into their own kind "Heating · PV surplus", and the new tile `pv_boost_share` shows the share of the heating time in PV surplus mode for today, yesterday and the week from the recorder history. The Lambda preset maps the E-Manager setpoint `emgr_power_consumption_setpoint` (W, register 104), so Lambda installations with the E-Manager get it without configuration. Other systems set `entities: pv_boost`. Only the time in which the PV entity has a known state counts for the share: without a PV history, or with only `unavailable` states, the tile shows a dash instead of 0 %.
- New option `valve_map` (raw state of the `valve` entity → `dhw` or `heating`) for a diverter or zone valve that does not follow "on = hot water", requested in #109. Example for a valve that reports 1 for heating and 0 for hot water: `valve_map: { 0: dhw, 1: heating }`. States outside the map keep the default reading, and the map applies to the timeline that is drawn from the compressor and the valve as well. The keys match a state in any case (`Tank: heating` also matches `tank`).
- New tile `dhw_loss`: standby loss of the hot-water tank in K/h over the last 48 hours from the recorder history. Only verified standby windows of at least 3 hours count; hot-water operation, the DHW heater rod, the solar pump, unknown states, draw-off and heating the card cannot explain are excluded with 30 minutes to settle. Unknown or missing compressor and valve states and a draw-off in the first 30 minutes of the history count as not verified. Needs a plain tank sensor at the top (not a thermostat entity) and an operating mode or compressor entity. The tile shows a temperature rate, not an energy (#32); an energy balance from heat meters is tracked in #114.
- Power sources: a source the installation does not have is no longer drawn. Without a battery (no battery entity in `power_sources: manual`, or none in the Energy dashboard) only PV and grid appear; a configured source that is unavailable stays dimmed as before (#102).
- Energy dashboard: several grid sources (for example two tariffs on one meter) count as configured when at least one of them has a power sensor, so the grid is no longer reported as missing and the PV / grid split stays live. The same power sensor behind several sources counts once. Several PV arrays or batteries still need a power sensor each (#103).
- Built-in languages beyond English and German can be contributed: a language is one entry in `HFC_LANGUAGES` plus a block in `HFC_I18N` and `HFC_EDITOR`, may be partial (missing texts fall back to English) and is selected from the Home Assistant language. The language list of the editor is built from them, and the visual editor follows a built-in language, too. `npm run i18n:check` verifies the blocks and lists missing texts. Guide in `docs/TRANSLATING.md`, issue template "Translation".
- Editor: a regional language block (`pt-br`) is used when Home Assistant runs in that locale, then its language (`pt`), then English; before, the locale was cut to two letters.
- `npm run i18n:check` rejects a group where English has text, an empty group included, instead of reporting "i18n OK" for a translation that would show `[object Object]`.
- Stiebel ISG and Luxtronik presets: parts that are mapped by their readings (buffer, solar, circuits, counters) and report only after the card has started are found within a minute, without reloading the card. A sensor that drops out for a moment does not remove a mapping.
- Radiators and column radiators: the ribs show the flow and return colours again instead of black. The card defined the gradient `g-rad` twice (once for the whole card, once for circuit 1); the ribs used the second one, which never got a colour. Only the circuit's own gradient is left.
- Kronoterm: preset documentation in `docs/presets/kronoterm.md`. With the Cloud API the heating pressure is the measured pressure only with Kronoterm 1.7.3 or newer; 1.7.2 and older report the setting of the low-pressure alarm (register 2325, 0.8 bar on the reference installation) under the same sensor. The card needs no change; it finds the sensor by its translation key.
- Luxtronik preset documentation: some controllers (reported on an Alpha Innotec WWC 100 H/X) leave `current_heat_output` at 0 and have no `current_power_consumption`. The README and `docs/presets/luxtronik.md` now describe the workaround with an own power meter and `heat: none` (#75).
