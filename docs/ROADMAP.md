# Development plan

This plan keeps correctness and supportability ahead of new surface area. Impact is the expected benefit across installations; effort is relative (`S` local, `M` several code paths, `L` public API or data logic, `XL` architecture or a second layout).

The next minor release starts with:

1. **Circulation program window** ([#34](https://github.com/Sturmi77/heatpump-hydraulic-card/issues/34); impact medium, effort S–M). Support one explicit start/end window from time or text entities and a Home Assistant schedule's next change. Missing values stay hidden. 2. **DHW loss from an energy balance** ([#114](https://github.com/Sturmi77/heatpump-hydraulic-card/issues/114); impact medium–high, effort M–L). Add a conservative period tile from explicitly configured cumulative heat-in, auxiliary-input and heat-out counters. Compute only when every configured path has valid statistics over the same period; never infer a missing heater or usage meter. Keep this separate from the existing temperature-slope tile and defer tank-volume conversion/comparison.

## Storage topology

Combined/layered storage ([#50](https://github.com/Sturmi77/heatpump-hydraulic-card/issues/50)), the wood stove ([#36](https://github.com/Sturmi77/heatpump-hydraulic-card/issues/36)) and a second heat generator ([#51](https://github.com/Sturmi77/heatpump-hydraulic-card/issues/51)) share one plan: [TOPOLOGY.md](TOPOLOGY.md). Weighted by prevalence, the card already covers about three quarters of installations, and combined storage plus a boiler in series bring it to about 90 %. The plan therefore starts with what helps in every case – a geometry snapshot test with a generated combination test, then one flow model – and adds combined storage (phase 1) and the boiler in series as fixed slots. An internal component model for the drawing is decided only before the rarer variants (wood stove, boiler in parallel), when further hydraulic requests justify it. Sprints 1 and 2 of the [sprint plan](TOPOLOGY.md#sprint-plan) shipped with 0.14.0: the snapshot and combination test and the flow model ([#111](https://github.com/Sturmi77/heatpump-hydraulic-card/pull/111)), one water loop without a parallel buffer ([#130](https://github.com/Sturmi77/heatpump-hydraulic-card/pull/130)), combined storage and `dhw_type` ([#133](https://github.com/Sturmi77/heatpump-hydraulic-card/pull/133)) and the edge cases found afterwards ([#134](https://github.com/Sturmi77/heatpump-hydraulic-card/pull/134)). The vendor-neutral boiler in series is scheduled for 0.17 with manual entities; diagnostic reports refine later preset mappings without blocking it.
